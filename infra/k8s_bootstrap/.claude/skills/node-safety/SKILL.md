# Node safety: preflight and snapshots

These nodes are borrowed from a shared Slurm cluster. The whole point of this machinery
is that we can prove we left them as we found them.

## Before installing anything

```bash
bin/k8s-preflight --workers 3 --snapshot
```

This selects trays from a single rack, checks each one, and captures the `pre` baseline.
It takes a few seconds — all checks run in parallel and are read-only.

Add `--nodes GPU-lb-rack-[0-3]` to check specific trays, `--rack lb/rack` to pin the rack,
or `--verbose` to see every PASS/INFO rather than just problems.

## The stale node-identity trap (read this one)

**A Slurm node name does not reliably reach the machine you think it does.** On dynamic /
cloud nodes, `NodeAddr` and cluster DNS both go stale: addresses get recycled and two Slurm
node records can point at the same physical host. Observed live on `polite-possum`:

```
scontrol: GPU-edaya-k2ssq-8  -> NodeAddr=172.16.39.176
dns:      GPU-edaya-k2ssq-8  -> 172.16.39.176
ssh:      GPU-edaya-k2ssq-8  -> hostname = GPU-ez4wq-56l4q-10   # a DIFFERENT node
```

k3s was installed on two machines that were never allocated to the job. Nothing else was
running on them that time, but the same slip could uninstall someone else's cluster.

Two things make it nasty: it is **intermittent** (a later sample of 40 idle trays showed
zero mismatches), and the wrong machine can be in an *excluded* localblock.

Always select through `slurm_pick_verified_trays()`, which checks every candidate tray's
`hostname` in parallel and silently skips mismatches. `assert_node_identity()` /
`assert_nodes_identity()` guard the install and teardown paths directly, for code that runs
without a full preflight. Preflight itself has a blocking `identity` check.

Never work around an identity failure by using the IP directly — that is the bug, not the
fix.

## When preflight fails

**Do not override it.** Every blocking gate protects the node, not us. Pick different trays.

| Failing check | What it means | What to do |
|---|---|---|
| `cni_state` | `/var/lib/cni` or `/etc/cni/net.d` exists | Node is in use or was left dirty. Use another. |
| `iptables` | Pre-existing `KUBE-`/`CNI-`/`cilium` rules | Same — someone's cluster state is still there. |
| `no_existing_k8s` | k3s/kubelet binary or unit present | Run `node/teardown.sh` on it first, then re-check. |
| `usr_local_bin` | `ctr`/`crictl` symlinks in `/usr/local/bin` | Host containerd tooling is shadowed. Investigate before proceeding. |
| `ports` | A required port is already bound | Something is listening. Do not kill it; use another tray. |
| `localdisk` | `/mnt/localdisk` missing or full | Cluster state has nowhere to go; node root is far too small. |
| `identity` | hostname != Slurm node name | Stale Slurm/DNS mapping. **Never override.** Selection skips these automatically. |
| `swap` / `cgroup` | swap on, or not cgroup v2 | kubelet will not run. Node is misconfigured. |
| `nvidia_runtime` | `nvidia-container-runtime` not on PATH | k3s cannot wire up GPUs at all. |
| *no output (unreachable)* | ssh failed, usually DNS | The tray is powered down. `sinfo` shows these as `idle*`, not `idle`. |

`WARN` does not block. The ones you will actually see: `fabric_state` or `clique_id` not
healthy means multi-node NVLink is unavailable on that tray, and `clock` means NTP is out
of sync, which will eventually break TLS and etcd.

## Proving a node was returned clean

`node/snapshot.sh` captures ~27 files per node into
`$STATE_DIR/snapshots/{pre,post}/<node>/`. Teardown captures `post`; the two are diffed.

```bash
bin/k8s-verify-clean          # once it exists (step 10)
```

The snapshot is deliberately **normalized so it diffs cleanly against itself**. If you add
a new captured field, verify that property or you will produce phantom drift forever:

```bash
# two consecutive snapshots of an untouched node must be identical
for d in /tmp/a /tmp/b; do
  mkdir -p "$d/$N"
  ssh "$N" "bash $PWD/node/snapshot.sh --outdir $d/$N --phase pre"
done
diff -r --exclude=meta --exclude='*.raw' --exclude=nvidia-smi.txt "/tmp/a/$N" "/tmp/b/$N"
```

Fields already known to churn, and how they are handled:

- `iptables-save` emits `# Generated by ... on <date>` comments **and** packet/byte
  counters in `:CHAIN POLICY [pkts:bytes]` lines — both stripped.
- IPv6 routes carry `expires NNNNsec` from router advertisements — stripped, and routes
  are sorted.
- Listening sockets include the ephemeral port range — filtered out using
  `/proc/sys/net/ipv4/ip_local_port_range`.
- `meta` (timestamp), `*.raw` (contain PIDs), `nvidia-smi.txt` (power draw, temperature)
  and `disk.txt` are captured for humans but **excluded from the diff**.

## NFS gotcha

`$STATE_DIR` is on NFS. **Always create a snapshot output directory on the controller
before asking a node to write into it.** The controller caches negative lookups, so if you
stat the path before the node creates it, the controller keeps returning ENOENT long after
the files exist. `snapshot_nodes()` in `lib/preflight.sh` does the `mkdir -p` for this
reason — do not remove it.

## Restoring vs classifying drift

Teardown actively restores paths, units, interfaces, eBPF maps, firewall rules and
`nf_conntrack_max`. Two things are classified benign instead, in `lib/drift.sh`: the three
networking modules k3s loads, and the empty `*mangle` table plus `net.bridge` sysctl key
that come with them.

**Do not unload those modules to "fix" the drift.** `modprobe -r` also drops dependencies
that become unused, so removing `br_netfilter` cascades to `bridge` and deletes the host's
`docker0`; removing `iptable_*` cascades to `ip_tables`. That was tried on a live node and
broke Docker. Recovery needed `modprobe bridge ip_tables`, `systemctl restart docker`,
`ip link set docker0 up`, and one container run to regain the IPv6 link-local — and the
bridge still came back with a different MAC.

## When a tray goes unreachable during teardown

`bin/k8s-verify-clean` reports it `UNVERIFIED` and exits nonzero. That is correct — the
absence of evidence is not evidence of cleanliness, and it must never be reported as clean.

Observed once: one of two trays reported residue, then went unreachable and sat in Slurm
`comp*` (completing + NOT_RESPONDING) while the other tray, torn down by the identical code
path moments earlier, verified pristine. Six other trays used the same session were all
`idle` and healthy, and `SuspendTime=INFINITE` ruled out auto-suspend.

**`SlurmdStartTime` is the field that settles it.** In that incident slurmd had restarted at
17:51:53 while `bin/k8s-down` did not start until ~17:52 and finished 17:53:27 — the node
was already failing about 90 seconds *before* teardown touched it, and `BootTime` showed no
reboot. The lease log's last line was `holding trays`, with no `releasing` entry, so the
trap never ran either: Slurm could not finish the epilog because slurmd was unresponsive.
Compare these three timestamps before concluding anything.

How to work out whether it was us:

```bash
scontrol show node <node> | grep -E 'BootTime|SlurmdStartTime|State|Reason'
cat "$STATE_DIR/teardown-logs/<node>.log"      # what teardown actually reported
sinfo -h -N -o '%N %t' | grep -c 'comp'        # is anything else stuck?
```

A `BootTime` older than the teardown means the node did not reboot. A `SlurmdStartTime`
*earlier* than the teardown means the node was already unhealthy when we arrived. Compare
against the other trays from the same run: if they are clean, the code is not systematically
at fault.

`provider_teardown_nodes()` keeps each node's teardown output in
`$STATE_DIR/teardown-logs/<node>.log` precisely so this question is answerable. It used to
discard it, which made one incident impossible to diagnose after the fact.

Re-run teardown once the node returns, then re-verify. Do not mark it clean from inference.

## Do not

- Do not weaken or skip a preflight gate to get a node accepted.
- Do not add a file to the benign-drift allowlist to make verify-clean pass. The allowlist
  matches exact module names and an empty table, never "this file changed".
- Do not `pgrep -f k3s` to detect an existing install: an `-f` pattern also matches the
  ssh command carrying the check, so a pristine node reports itself dirty. Check for the
  binary and the systemd unit instead.
- Do not write to the host's `/var/run/cdi/nvidia.yaml`. Its sha256 is part of the
  baseline; changing it is drift.
